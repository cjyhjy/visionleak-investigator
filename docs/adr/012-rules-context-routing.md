# ADR-012: Frozen rules-v2 context routing

The original rules-v1 selected profiles only from `request_text` before reading registered descriptions. Two real Core runs reproduced the gap in `reports/rules-context-gap-v1`: a rotation clue in a registered Markdown document produced base only, while the same clue in the request produced base plus transform. This was narrower than the planned C baseline.

Rules-v2 performs mandatory base, then one charged deterministic context/metadata interpretation, then a bounded routing decision. It uses the request and the saved first 8,000 characters of registered Markdown/TXT documents. CSV cells, image filenames and candidate counts do not supply routing clues. The frozen literal term lists and limited immediate-prefix negation are explicit in `configs/policy.json` and its schema. They do not provide general language understanding; negation spanning clauses, synonyms outside the term list, and conflicting descriptions can still cause missed or unnecessary checks. A positive clue is a reason to inspect, never evidence that a transform or source relationship exists.

Transform/local clues select transform/local, or one all scan when both occur. No positive clue leaves local and transform checks off. Incomplete or unverified base, insufficient audit count, tool/time finalization reserve, comparison/index allowance, or full-source decoding plus conservative verification allowance defer the supplement and retain a PARTIAL coverage gap. Metadata interpretation still asks only missing host confirmations within the question budget. It does not infer physical identities or confirm a goal from text. Both positive and ignored negated clues, source/excerpt digests, metadata state, questions, remaining budget and the actual outcome are recorded.

A and B remain independent one-pass base/all baselines. Explicit profile lists keep their caller-selected behavior. Scripted Planner callbacks remain labelled tests and do not inherit rule decisions. The shared audit dispatcher now enforces the first-version maximum of three actual Core attempts even when TaskSpec supplies a larger limit; this closes the path where a scripted controller could previously exhaust all four distinct profiles. Thresholds, evidence validation, permissions and Core code remain fixed.

Each automatic rules run captures `rules-policy.json` and `rules-decision.json`, bound by validation hashes and report/manifest identities. Goal/review revisions copy the accepted initial routing with an explicit no-rerun scope; conservative recovery quarantines unaccepted routing files. The new policy/configuration and implementation require a new evaluation freeze. Historical v1 results are preserved and are not relabelled as v2 or as live Agent evidence.

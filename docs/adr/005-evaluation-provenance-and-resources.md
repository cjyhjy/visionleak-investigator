# ADR-005 · Resource accounting and evaluation provenance

Status: implemented locally; acceptance receipts and platform results are recorded separately.

Each A/B/C engineering task runs in an isolated Python child that invokes the same actual Core implementation. The host records command, stdout, stderr, exit code, wall time and resource measurements. `os.wait4` supplies user/system CPU accounting including reaped descendants. `psutil==7.2.2` samples the root and recursive children every 20 ms and records the largest observed simultaneous sum of RSS. Individual Core commands retain the same measurements. Do not sum nested CPU receipts and the whole-task CPU receipt: that would double count.

RSS is neither a hard limit nor unique physical memory. Shared pages can be counted twice, very short processes and peaks can be missed, and detached/unreaped children are outside complete CPU accounting. Access denial produces `tree_rss_peak_bytes=null` with partial/not_measured status; root-only observations remain separately labelled. Timeouts kill the created process group and preserve available CPU/RSS plus the actual negative exit status. Spawn failure has no measurement. Aggregation retains failed and partial runs and distinguishes missing costs from zero. A process restart does not flush the OS cache.

The engineering evaluator freezes Core/runtime, source code, policy, Python lock and installed base library identities, checks before/after every condition, and compares input identities and total limits. A mismatch leaves raw artifacts plus a rejection record and stops aggregation. Historical reports without these additional fields remain historical evidence; they are not retroactively upgraded.

The evaluator-only source catalog records URL/generator identity, acquisition time, license evidence, redistribution restrictions, content hash, parent images, source/entity/session groups and explicit known-Core provenance. Connected sources and every source used by a task form one sampling unit, including shared negatives. A component cannot cross development/validation/test. The pinned Core history includes old photo manifests and candidate-source URLs; recognized content/origins or declared known data are restricted to development. Before reading history through the Core digest helper, the installed Core artifacts are verified.

Every task image must map to a checked source. All truth paths and exact truth-content hashes are checked against every task's registered datasets/documents. This prevents accidentally supplying another task's truth. The freeze also binds task/registry/truth/input/document identities, conditions, repetitions, metric definition and explicit model configuration. Its digest is a consistency check, not a signature against a local administrator. Labels do not establish real physical identity or legal rights, exact-match checks do not detect every transformed/embedded answer, and before/after hashing is not an atomic snapshot.

`eval-check` only checks a configuration; no live provider or independent test result is implied. The catalog-driven experiment runner and natural validation/test collection remain unfinished. `scripts/evaluation_gate_smoke.py` uses clearly marked procedural fixtures to verify the CLI and rejection gates in separate processes. The original catalog still verifies after negative tests. No model or network request is needed.

References for measurement semantics: [Python resource usage](https://docs.python.org/3/library/resource.html), [Python wait4](https://docs.python.org/3/library/os.html#os.wait4), [psutil process memory](https://psutil.readthedocs.io/en/latest/#psutil.Process.memory_info), [psutil children](https://psutil.readthedocs.io/en/latest/#psutil.Process.children).

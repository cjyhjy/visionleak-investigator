# 阅读本地审计报告

先看页面顶部的执行状态和模式。`COMPLETED` 表示列明范围检查完成，并不表示数据没有风险；`PARTIAL` 表示存在未覆盖范围或异常；`WAITING_USER` 表示有需要确认的问题或已请求的复核。`SCRIPTED_TEST_ONLY` 是控制器测试，不能解释为真实模型决策。

“待办与问题”列出澄清问题、尚未请求的问题、复核状态和异常。候选没有请求人工处理时仍显示，不能从队列中消失。修改目标或导入复核结果仍使用 README 中的 CLI；静态页面本身不修改数据。

“目标与检查范围”将已发现、已生成指纹和已处理的图像数分开，并显示 Core 的停止原因。生成指纹不等于已完成图像比较。元数据中的实体标识属于登记声明，不能替代独立身份核验。

“结论”里的编号链接到本页相应证据卡片。卡片保留文件名、Core 缩略图、原始 JSON 位置和复验状态。原始 JSON 的 `/pairs/N` 指出条目位置；浏览器打开的是完整 JSON，并不保证自动滚动到该条目。候选的 `exact_recomputed=not_applicable` 不能解释为精确复验通过。人审不会修改 Core 证据类型。

“预算”显示累计已扣账与总上限。“审计扫描调用”包括被预算中断的调用，不是完成次数。`unknown` 调用按预留保守扣账，不冒充实测。工具墙钟与完整任务 CPU/进程树 RSS 是不同计量；后者在独立评测记录中查看。脚本规划器的请求不计作真实模型实验。

采用单次渲染的新页面会醒目标明“结案结算前的预算快照”：页面中的当前结案条目可能显示 pending，最终累计值与结算时间请打开同页链接的 `ledger.json` 或 `report.json`。JSON 报告包含已结算账本。渲染、报告内容序列化和暂存写出计入结案操作；记录计量值本身的提交步骤由完整任务资源收据覆盖，计量范围见 `publication` 字段和 ADR-014。结案超时的主页面只显示 PARTIAL 状态与最终记录链接，原页面作为未接纳快照保留。

“执行记录”取自预算账本的调用顺序与预留/结算时间。修订页面包含复用证据的历史调用，并醒目标注“未重跑 Core”。原始身份、状态事件、证据、覆盖和预算文件都有独立链接。

安全边界：文本和属性转义；证据片段 ID 由摘要生成；图片和原始 Core 报告只接受当前报告中允许的固定路径形式。页面没有 JavaScript、表单、外链字体或远程图片。输入变化时不显示已撤回证据的卡片；恢复不把未接纳的原始产物显示成有效事实。页面呈现不能代替 `vli report` 的记录完整性校验。

新版页面从新的运行生成，不重写历史 HTML。桌面与窄屏 Chrome 的实际验收记录单独保存在 `reports/visual-review/`；其他浏览器的渲染兼容性不能据此推定。

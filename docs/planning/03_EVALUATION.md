# 03｜评测设计：证明价值，而不是证明用了 AI

## 1. 分开回答三个问题

**工程正确性**：真实 Core 是否被正确调用？证据和不完整状态是否被保留？是否越权、改数据或错误计费？

**产品价值**：在目标/元数据不完整时，是否减少用户手工准备和反复核对？能否提出必要问题并解释结果？

**研究增益**：同工具池、同数据和可比预算下，Agent 或 Harness 优化是否优于强规则？

三者单独写结论。测试通过不等于算法领先；报告漂亮不等于节省成本；合成数据结果不等于真实场景成功。

## 2. 首版四组实验与可选第五组

| ID | 条件 | 实际实现 |
|---|---|---|
| A | Core 基础 | 一次 base，全目录；输出同款确定性报告 |
| B | Core 全开 | 一次 all，全目录；同一总计算预算；不人为压低参数 |
| C | 强规则 | base 后根据可见说明、元数据完整性、配置和预算做升级/追问；规则明确可重放 |
| D | 固定 Agent | 单模型、冻结提示/策略；使用相同白名单工具与预算 |
| E | Agent + 策略优化 | 只将开发/验证集选出的冻结策略替换 D 中策略，其余相同 |

### 必须遵守

- 首版主比较是 **C vs D**；第二阶段再比较 **D vs E**，而不是只比最弱的 A。
- 图像检测比较给所有条件同一个经过确认的 TaskSpec，避免把“有没有获得目标/元数据”混入检测收益。
- 交互比较另开任务：相同信息权限、相同可回答问题集合，规则系统也可以询问目标和字段含义。
- 所有检测参数、工具版本、文件顺序、输入清单与数据变换固定；所有基线都获得同样工具能力。
- 图像检索统一 comparisons 总预算；总成本另记 CPU/时间/内存、模型、人工、重试和优化。没有 LLM 的规则基线成本确实可更低，不给它人为附加无用调用。
- B 的单次 all 可能比逐轮扫描更便宜；这正是需要面对的强基线，不应改成低效版本照顾 Agent。
- warm/cold cache 分开；首版默认 cold、完整 CLI 重跑，不跨条件共享未计价缓存。
- 真值与评分器不进入 Agent 可读工具；不可联网查找测试答案。
- 已知失败、超时、不完整、被拒绝数据全部保留，不能只统计成功 run。

## 3. 数据设计

### 3.1 双重 partition 不能混淆

每个审计任务内部有 image_split：train / validation / test。

评测平台把“整个任务及其原始来源组”划到 benchmark_partition：development / validation / test。

同一原始照片及其所有变换副本、同一实体/拍摄会话，不得跨评测平台的 partition。图片对数量不是独立样本量，统计区间按任务或原始来源组计算。

### 3.2 已有 Core 数据的用途

Core 历史合成集、10 张旧照片、0.5.0 的 32 个来源及其开发/留出组，均视为本项目已知数据，只作集成/回归或 development。[S1]

尤其不要拿已经阅读、用于规划和选择策略的旧 holdout 再叫“全新独立测试”。最终 test 必须使用新来源、新来源分组、新任务实例；策略冻结后才使用。

### 3.3 分层样本

| 类别 | 示例 | 真值来源 |
|---|---|---|
| 精确内容 | 复制、改名、无损重编码 | 独立文件/像素关系与生成记录 |
| 受控变换 | 镜像、直角旋转、缩放、局部裁切 | 独立生成器的来源 ID 与变换参数 |
| 难负例 | 平色、相同梯度、同类不同实体、相似纹理 | 不同原始来源/人工核验 |
| 目标敏感 | 同实体多视角跨 split | 元数据 + 明确实验目标 |
| 信息缺失 | 目标未说明、实体字段含糊、元数据缺行 | 固定任务契约及模拟用户答案 |
| 输入与覆盖 | 坏图、未知格式、预算耗尽、文件变化 | 真实文件操作与独立预期 |
| 对抗说明 | 文档试图指使忽略规则、读取密钥 | 安全用例，不是用户授权 |

受控变换图不等于在真实公开数据集中发现自然泄漏。局部裁切不能只与 Core 的固定窗口对齐，要加入非对齐位置、比例与混合变换。变换名称不出现在 Agent 可读文件名、目录、任务 ID 或元数据中，避免泄露答案。

### 3.4 建议起步规模

- 工程 smoke：至少 12 个任务，用于调试，不宣称研究结论。
- 开发/验证：各不少于 10 个小任务，优先增加独立来源与任务多样性而非同图重复变换。
- 冻结 test：目标不少于 30 个独立任务；若授权/数据不足则提交已有结果并写清样本限制。
- 真实模型条件 D/E 建议每任务 3 次独立运行，记录随机性；正式次数必须在看 test 结果前固定。

这些是建议实验预算，不是功效分析结论，不保证显著性。资源紧张先完成公平小样本比较，不用大量合成 pair 冒充大规模验证。

### 3.5 数据授权与隐藏真值

允许的初始来源：自行生成、用户有权提供、许可已记录的公开素材。每个来源记录 URL/许可/获取时间/内容摘要/再分发限制。没有许可记录不进入公开交付。

生成与 evaluator 使用的 truth.json 不能放在待审计目录、模型上下文或注册工具可读范围。运行 Agent 只得到约定输入；评分由独立进程读 truth。应用隔离不等于对本地管理员的密码学保密，报告应如实说明隔离方式。

## 4. 指标与分母

### 4.1 图像关系检测

- 精确重复：TP/FP/FN 单独计算，基于文件/规范化像素定义，不与感知候选合并。
- 同源变换候选：pair precision、recall、F1；排除精确 pair 后另算近似分母。
- 候选负担：每 1000 张图候选数、待复核 pair 数、无效候选数。
- 若候选未全部标注，precision 记 unknown 或只报告明确标注子集；不得只挑确认成功的候选计算 precision。
- 无正例时 recall 为 N/A；无预测时 precision 按预登记规则为 N/A，不能写 100%。

### 4.2 目标解释与实体风险

- 目标识别正确率；是否对真正缺失目标提出必要问题。
- 元数据字段解释正确率；无依据实体身份断言数量。
- risk precision/recall 使用按任务目标预定义的风险真值，不能由 LLM judge 临时生成。
- 结论引用合法率、unsupported-confirmed claim 数量。
- 已知正常场景误报与过度澄清次数。

### 4.3 完整性与资源

- profile 完成率、有效图片/元数据覆盖、因预算/输入问题未完成的比例。
- comparisons 总数；CPU/墙钟；峰值 RSS（注明测量方式，不能只测 Python 母进程漏掉 Node）。
- LLM 请求数、各请求 usage、成本来源、失败与重试。
- 人工澄清数/复核数；只有真人实际参与才能报真实节省工时，模拟用户不产生“人工时间降低”结论。

不能只统计 Agent 选择检查的简单子集。首版完整目录扫描避免选择性分母；将来引入子集采样时，未覆盖样本仍在全量真值分母中。

## 5. 策略优化流程

1. 冻结任务定义、不可变 Guard、工具池、指标和默认 D 策略。
2. 记录提案器模型/版本和预算。第一轮最多 3 个候选；仅改被允许的策略配置。
3. 在 development 全套预登记任务上跑候选，独立 evaluator 计分；失败照常入表。
4. validation 选择候选；优先满足安全/证据约束，再看质量—成本权衡。不以候选数作为收益函数。
5. 生成 `policy_candidate.json`、`selection.json`、不可变 `policy_frozen.json` 与 digest。
6. D/E 用完全相同的固定 test、模型、预算和重复次数比较。不能让 E 继承其他 test 任务的隐式记忆。
7. 结果不理想，发布负结果，不能回头改 test 或隐藏成本。

没有真实模型授权时，配置候选枚举与离线逻辑测试可以做，但 `llm_policy_optimization=not_run`。不得把手写策略网格搜索说成大模型自主优化。

## 6. 成本账本与摊销

每次审计实际成本：

`C_online = 所有模型调用 + 全部工具调用/重试/取证的已计资源 + 记录的人工介入`

不同成本单位分别报告，不把未定价 CPU 秒或人工次数强行变成美元。

若离线优化花了 C_opt，则给定明确部署次数 N 时：

`C_per_task(N) = C_online + C_opt / N`

同时列 C_opt 原始值、未摊销结果和 N 的假设。若新方案每次在线只节省 ΔC>0，则理论成本回收任务数为 `ceil(C_opt / ΔC)`；ΔC≤0 时不能说可通过摊销回本。不要凭空假设十万次调用掩盖本届项目成本。

## 7. 发布结论与阶段闸门

### 必须通过的工程条件

- 未授权写源数据/外发/超预算为零；人工确认不被伪造。
- 确定性证据不会无依据升级，报告引用有效，已知精确证据回归无解释外退化。
- 不完整不被宣传成无风险；真实 Core 流程与 scripted/model 证据区分。

### 可以争取、不能先写成成果的研究目标

D 相对 C，在任务正确性不下降的前提下减少人工准备/复核，或在相同预算下发现更多有真值支持的风险。E 相对 D，证明策略优化值得其额外成本。

“降低 20% 成本”“提高 10% 检出”之类数字只在测得且定义明确时出现。需要非劣效/显著性时先登记容忍差值与统计方式；样本不足就报告区间和不确定性，不硬凑结论。

### 三条停止/收缩规则

- D 不优于 C：保留自然语言目标澄清能力，检测采用强规则；不称自适应检测优越。
- E 不优于 D 或优化成本过高：关闭离线 Harness 优化默认入口，保留研究实验记录。
- 只有 mock/replay：产品是工程原型，尚不能称真实模型 Agent 已验证。

## 8. 输出文件

`evaluation_manifest.json`、`source_split_manifest.json`、`frozen_config.json`、`per_run.jsonl`、`metrics.json`、`failures.jsonl`、`costs.json`、`summary.md`、原始工具日志索引、数据来源/许可表。

报告必须含：测试任务数、独立来源数、已运行/失败/未运行数、每种条件、模型与 Core SHA、用户授权模式、预算、随机设置、真值隔离方式和全部局限。

## 首版评测与 Core 版本控制（0.6.0 修订）

首版完成 A—D，主要检验 C vs D；E/M4 另行立项，未运行必须显示 not_run。所有条件使用同一 core.lock、capabilities、profile、阈值、文件顺序和数据。Core 升级另做版本对照，不把 MIH/内存优化收益混入 Agent 收益。

A/B 是独立的确定性评测驱动；B 直接运行一次 all，不执行生产 Agent 的强制 base 步骤，也不能因此放宽 C/D 的门禁。预算相同指相同总上限，不强迫规则系统耗尽额度。comparisons、indexOperations、源像素解码量、时间/RSS、模型和人审分别报告；重复扫描实际计费。

0.6.0 新增的合成规模数据与旧照片回归同样属于已知数据，不充当 Investigator 的独立 test。独立来源不足时只交工程结果与可重放小规模试验，不给统计显著性或自然场景泛化结论。

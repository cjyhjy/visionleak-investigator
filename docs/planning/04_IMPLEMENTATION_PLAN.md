# 04｜分阶段实施与验收

## 执行原则

这是执行顺序，不是对工期或比赛结果的承诺。先完成可验收的纵向流程，再扩展研究功能。无凭据时继续离线阶段，不原地等待；真实模型受阻项单列。

每个阶段保存：开始/结束状态、实际代码版本、测试命令、输出路径、退出码、通过/失败/未运行、已知问题、下一步。不要把勾选任务等同于测试通过。

## M0｜核实基线与建仓

**任务**

- M0.1 检查工作目录与权限，在授权位置建独立项目；保留原 Core。
- M0.2 锁定 Core 提交、核对 package、CLI、报告 schema、许可证、源/产物摘要。
- M0.3 独立依赖目录安装并运行真实 smoke：正常、确定性重复、预算不完整、verify 失效。
- M0.4 选择一个可用的 openJiuwen 精确版本，验证 Python 3.12/macOS 或 Linux 下导入与一个无模型工具工作流。只实现已查明接口。
- M0.5 生成环境与状态文件、项目锁文件、权限配置、ADR-001 技术栈。

**验收**

`reports/milestones/M0.md` 必须包含实际四类 CLI 行为。Core 拿不到时集成 blocked，不能自行实现替代检测。openJiuwen 不兼容可以先把业务层做完，但保存错误，不宣称已适配。

**首个对用户反馈的检查点**：真实依赖、目录和接口是否可用，哪些约束已经写入测试。

## M1｜确定性审计闭环（尚不是 Agent）

**任务**

- M1.1 TaskSpec/AgentAction 类型、JSON Schema 与登记 registry；输入校验。
- M1.2 CoreAdapter：argv、超时、退出码、原始报告、内容身份、路径隔离。
- M1.3 EvidenceStore、CoverageLedger、BudgetLedger 和 run manifest。
- M1.4 base/full profile 调用；记录所有重扫开销；真实输入不变性检查。
- M1.5 确定性 ClaimValidator、模板报告与最小 HTML。
- M1.6 CLI `doctor` / `run --mode rules` / `report`；正常与部分结果可复现。

**验收**

从干净目录使用合成图实际运行；输出真实报告、工具日志和 ledger；源文件摘要不变。检测到候选和预算耗尽都必须有正确报告，不可直接抛异常丢证据。

**不允许**：先做一个好看的前端，再用硬编码数据占位，称系统已完成。

## M2｜目标、元数据与人机交互

**任务**

- M2.1 读取登记的 Markdown/TXT/CSV；文档视作不可信数据。
- M2.2 新实体/同实体新视角/内容审计规则；目标确认与字段语义确认。
- M2.3 澄清请求、人工复核、WAITING_USER、answers/review 导入。
- M2.4 checkpoint 与 resume；目标修改产生 revision，输入变化拒绝无条件续跑。
- M2.5 只读建议 manifest；保护 test；不改变源图片、不自动训练。
- M2.6 实现透明强规则策略 C：有相同工具和询问权限；异常处理与预算逻辑不弱化。

**验收**

同一元数据的两个不同目标产生预期不同实体风险结论；缺字段/目标未知不会臆断。重复恢复无重复开销；人工复核不升级 Core 证据等级。

## M3｜真实单 Agent 集成

**任务**

- M3.1 建立 openJiuwen 工作流适配层；业务状态机与安全门禁可独立测试。
- M3.2 单 Planner 读取脱敏观察并输出 AgentAction；仅注册白名单动作。
- M3.3 实现无模型 scripted planner，**只用于测试**；真实模式与 replay 模式在 CLI/报告醒目区分。
- M3.4 真实模型 adapter：用户明确配置 provider/model/base URL 与授权预算；TLS 验证开启。
- M3.5 ActionGuard：非法字段、未知证据、预算穿透、重复调用与越权动作拒绝。
- M3.6 至少两条有授权的真实模型端到端轨迹：一条主动澄清，一条补充取证或合理停止。追踪模型请求/usage/失败。

**验收**

真实 Agent 的决策确实影响动作，工具真实运行，结论通过独立 ClaimValidator。没有模型授权：M3.1—M3.5 可完成，M3.6=blocked；不能用 scripted 轨迹代替。

**最低可演示版本**：M0—M3 的真实模型部分完成，配三分钟可复现的受控案例。不宣称算法优越。

## M4｜第二阶段：领域化 Harness 策略试验

**任务**

- M4.1 定义 policy schema、不可变参数/可改参数白名单与 hash。
- M4.2 提案器生成最多 3 个合法候选；无 arbitrary code 或动态 import。
- M4.3 evaluator 与 Agent 权限隔离；实现 A—E 条件运行与总成本记录。
- M4.4 development 试验、validation 选择、冻结 policy；test 不学习、不改配置。
- M4.5 加入负结果处理，优化成本与多轮重扫成本单独列出。

**验收**

能拒绝偷偷改证据门槛、真值路径、数据权限或预算的候选。选择记录可复核。无 LLM 运行时仅完成管线与配置枚举测试，不称真实 Harness 自动改进成功。

**优先级**：真实 Agent 端到端未稳定前，不做递归自改进、不扩充工具池。

## M5｜独立评测、演示与交付

**任务**

- M5.1 新来源划分，冻结规则/模型/策略/预算；原 Core 数据仅回归。
- M5.2 首版公平跑 A—D，第二阶段增加 E；失败与不完整不丢弃；各条件可重放。
- M5.3 完成本地证据页：目标/检查范围/时间线/证据/复核/预算/局限，不先做账户系统。
- M5.4 一条命令生成合成演示输入；保存生成种子与真值隔离记录。
- M5.5 README、架构、API、AI 使用与来源声明、许可清单、研究结果和已知失败。
- M5.6 创意稿、≤3分钟演示脚本、现有成果/新增成果边界；不自动提交赛事。

**验收**

干净环境复现；真实模型/离线模式清楚区分；无秘密/客户数据进入交付；不能宣称未测的精度/成本收益。正式公开前检查跨赛复用、IP、外部数据与发布授权。

## 关键测试矩阵

以下是最低验收类别，不是要求只写这些测试。每类都要有实际 fixture 和断言。

| ID | 输入/故障 | 必须观察到的结果 |
|---|---|---|
| T01 | 跨 split 字节相同图片 | 真实 Core 确定性证据；报告引用正确 |
| T02 | 不同编码、规范化像素相同 | 仍保持 pixel 证据，不错写 byte |
| T03 | 镜像/旋转、局部裁切样本 | 候选保持 candidate，不能自动升级 |
| T04 | 平色/梯度相似负例 | 允许候选但不自动判泄漏；误报进入评测 |
| T05 | 比较预算耗尽 | PARTIAL、coverage 缺口、不得宣布无风险 |
| T06 | 坏图/未知格式/拒收大图 | 覆盖缺口可见；正常证据仍保留 |
| T07 | Core code 3 / verify code 4 | 命令级语义正确，不一律当崩溃 |
| T08 | 同实体、新实体泛化目标 | 目标确认后按规则判冲突 |
| T09 | 同实体、新视角目标 | 不仅因实体重叠判错误；内容事实不变 |
| T10 | 未说明目标/字段意义 | 有必要追问；WAITING_USER 可恢复 |
| T11 | entity_id 缺失/矛盾 | 不编造身份；范围与问题清楚 |
| T12 | 修改文件后 resume | 检出数据版本变化，旧证据不能静默复用 |
| T13 | 伪造 evidence_ref | 动作/结论被拒绝，记录原因 |
| T14 | 非法 JSON/未知 action | 有限纠错；计入调用预算 |
| T15 | 文档要求读密钥/删除测试集 | 不执行；模型输出也不能越过门禁 |
| T16 | 多轮重复相同 profile | 拒绝空转，不重复计费/覆盖原报告 |
| T17 | 超时/崩溃/半截报告 | 清理子进程；保留失败，预算保守核算 |
| T18 | 工具结果目录穿越/symlink | 拒绝；源目录无写入 |
| T19 | HTML/CSV 注入字符串 | 安全转义，无脚本/表格公式执行 |
| T20 | 远程模式无授权/仅有 key | 不发网络请求；blocked 状态明确 |
| T21 | 归档复核应用到新 auditId | 拒绝或显式重新确认 |
| T22 | optimizer 修改 Guard/真值 | schema/语义拒绝，不能采纳 |
| T23 | Agent 试读 test truth | registry/运行权限隔离；测试可证实 |
| T24 | 核心未运行但 replay 完成 | 报告不能写真实模型/实测性能 |
| T25 | 新 manifest 建议 | 原数据与 test 不变，需批准，注明重训边界 |
| T26 | 预算在纠错/验证中耗尽 | 所有开销入账；无“最后一步免费” |
| T27 | all 基线与 Agent 不同预算 | evaluator 拒绝不可比配置或单独标记 |
| T28 | 因少报候选看似 precision 上升 | recall 与全量复核负担同时保留；不裁分母 |

## 持续集成

- PR/本地默认无模型、无网络业务执行：单元、真实 Core smoke、契约、安全、报告、恢复、核心输入不变性。
- 安装依赖的联网与审计运行联网权限分开。
- 大规模、公开新数据与付费模型实验使用手动授权的独立任务，结果不混入离线 CI。
- Core 版本升级是显式变更：更新 lock、重跑契约/回归，保留旧结果。

## 完整交付清单

源代码、锁文件、AGENTS.md、README、核心依赖 manifest、所有契约、受控演示生成器、真实 Core 集成测试、可脱敏 trace 示例、评测脚本与原始结果索引、阶段报告、已知局限、第三方许可和 AI 辅助说明、申报草稿。

**不含**：用户 API key、真实私有图像、未授权公开数据、假造指标、自动报名凭证、核心项目的重写或重新许可。

## 修订后的交付顺序与补充验收

首版顺序：M0 → M1 → M2 → M3 → M5.1—M5.6（评测 A—D）。M4/E 为第二阶段，不阻塞首版。M0 还需跑 capabilities 并与 core.lock 比较；导出 JSON Schema 通过不代表实际接口兼容。

补充用例：

- T29：只有 local-candidate 的报告，verify 退出 0、valid=0、skippedCandidates>0，结论仍为候选。
- T30：生成指纹数大于 processedImages，明确未覆盖后缀，不能声称精确检查完整。
- T31：跨三次 audit/verify 分配像素与索引预算，预留结案额度，超时保守结算。
- T32：CSV split 与目录冲突/平铺目录拒绝，不能空扫描后报无风险。
- T33：合法 evidence_ref 支撑不了 claim_type 时拒绝断言；人为同源确认不升级成 pixel-identical。
- T34：新 schema/profile 或产物摘要不符时拒绝；允许已知 schema 中无害新增字段。
- T35：A—D 的 Core 锁不同则评测不可汇总；恢复无重复计费，goal-only revision 可追溯复用已验证图像证据。

上述是待实施验收要求，不是本次规划修订已经完成的 Investigator 测试。

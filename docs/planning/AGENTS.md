# Agent implementation instructions

这是 VisionLeak Investigator 的设计与开发任务包。服从用户工作区内更高层的安全与权限要求。

## 目标与范围

- 实现图像数据集审计单 Agent，复用 VisionLeak Core，不开发第二个通用聊天助手。
- 新项目独立于 MoonBit 黑客松的 Core；已有功能不冒充新增贡献。
- 第一版支持：图像跨 split 内容审计；带可信实体元数据的新实体泛化/同实体新视角目标检查；受预算约束的工具选择；人工复核；可追溯报告和只读修正建议。
- 不做自动训练模型、全论文复现、任意网站抓取、复杂 PDF/OCR、自动改数据、自动修改 Core、多 Agent 蜂群或通用代码执行。

## 执行约定

1. 先读设计和现有仓库，再写测试与实现。保存实际命令、版本、退出码和日志路径。
2. 所有“完成”必须对应验收证据。没运行写 not_run；被阻塞写 blocked；失败保留失败信息。
3. 单元测试可使用 stub；端到端、对照实验、展示结果必须使用真实 Core。scripted/replay 模式醒目标记，不称真实模型 Agent。
4. 编写并锁定依赖；不要编造 openJiuwen 类名、方法或支持能力。采用已安装并通过契约测试的 API。
5. 没有授权的付费模型或联网操作，不尝试从浏览器、钥匙串、其他项目配置或历史日志搜凭据。仅使用用户明确配置的当前项目凭据。
6. 不把整个数据集、源码、图片、自由文本元信息默认发给外部模型。默认仅本地；授权远程时遵循数据级别与允许字段。
7. 不公开推送、不创建外部仓库、不发布 npm/Mooncakes 包、不正式报名、不接受比赛条款。上述事项需要负责人另行授权。
8. 不覆盖原 Core 工作树；依赖用固定提交的独立副本。发现 Core 缺陷，记录最小复现及可选上游补丁，不偷偷更改已发布 Core。
9. 不删除/移动源图片，不改训练/测试划分，不替用户确定科学目标。所有修正计划均是建议文件。
10. 不降低验收标准以通过测试；不以“多找候选”作为准确率提高；不将未知/未完成/未调用写成零风险/成功。

## 工作方式

- 按修订后的 M0→M1→M2→M3→M5 首版子集顺序，M4/E 留作第二阶段，尽量完成所有不依赖外部批准的工作。
- 每阶段更新 `WORKLOG.md`、`STATUS.json`、`reports/milestones/Mx.md`。
- 状态必须区分 `passed`、`failed`、`blocked`、`not_run`；模型与真实数据实验证据独立于离线测试。
- 可以在新项目创建局部虚拟环境和锁文件；不改变全局 Python/Node/代理配置，不停止其他服务。
- 使用可恢复的子任务，不在每一步重复询问是否继续。关键架构偏离写 ADR，非关键选择用规格默认值。
- 首版优先 CLI 与静态证据页，不先搭复杂前端。

## 数据和评测隔离

- Core 已使用过的所有照片、回归集与历史 holdout 只能作为本项目开发/回归数据，不能宣传为全新独立测试集。
- Agent 的工具、提示词、策略优化器均不得读取最终测试真值。
- 数据集内 train/validation/test 与评测平台的 development/validation/test 是两个维度，字段名必须区分。
- 公开报告中逐项说明哪些是合成、受控变换、真实业务、真实模型调用或离线回放。

## 代码质量

- Python 类型标注；业务逻辑与框架适配解耦；严格验证模型返回的结构化 action。
- subprocess 必须 argv 数组、shell=False、有时限、工作目录与输出路径约束。
- 模型不可提供 shell 命令、任意路径或新的工具实现。
- 使用真实报告验证、原图不变性测试、预算超限测试、提示注入测试和恢复测试。
- HTTPS 证书校验开启；禁止复制示例中的 verify_ssl=False。
- 本地 HTML 自动转义；资源白名单；不把本地端口绑定到 0.0.0.0。

## 完成定义

可从干净环境按 README 复现；真实 Core 集成通过；每条结论有证据位置；完整性与预算如实显示；缺少模型授权时明确标为未验证真实 Agent。论文式收益结论必须来自冻结方案下的独立实验，功能验收通过不等于算法优越性成立。

当前 Core 执行依赖以 core.lock.json 为准，SOURCE_BASELINE.json 是历史核查，不允许据其旧推荐提交覆盖新锁。开始实现前读 07_CORE_INTEGRATION.md；不要因 0.6.0 版本号而假定 v2 裁切、缓存、增量或语义泄漏检测已经可用。
